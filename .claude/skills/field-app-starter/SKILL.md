# 現場アプリを作る（SBS配送ツールの作り方を再利用する）

骨組みは `starter/` にある（このリポジトリの中。テンプレートリポジトリに分けていればそちら）。
まず `starter/README.md` を読み、構成と設置の流れをつかむ。

## 1. 始める前に、利用者と決めること

- 誰が使うか（区分）と、それぞれが見てよい範囲（自分の分だけ／会社の分／全員分）
- シートに置くタブと列（1 タブ＝1 表。1 列目は ID にして、送り直しても行が増えないよう上書きにする）
- AI に任せるところ（読み取り・文の手直しだけ）と、決まった計算で行うところ（お金・数・割り振り・重複）

聞き返さずに決められる細部（見た目・文言・列の順など）は、ふつうの選び方で決めて報告に書く。

## 2. ひな形から作る

1. `starter/` の中身を新しいリポジトリの最上位へ写す（`cp -r starter/. <新しい場所>/`）
2. 業務に合わせて書き換える。だいたいこの3か所でよい
   - `apps-script/endpoint.gs` … タブの見出し・`doPost` の `switch` に action を足す
   - `api/<名前>.js` … 入口で `requireUser`、入力は `src/domain/` で整えてからシートへ
   - `public/index.html` … 画面（`api()` でサーバーを呼ぶ）
3. 新しい API は `functions/api/[[route]].js` の `ROUTES` に足す
4. 試験は `test/app.test.js` と同じ形で足す（`loadAppsScript` が本物の .gs を模擬シートで動かす）

## 3. 守ること

- 権限は API とシートの**両方**で確かめる（画面で隠すだけにしない）
- 合言葉（TOKEN）・利用コード・API キーはコード、コミット、PR、チャットに書かない。ホスティングの環境変数にだけ置く。
  push の前に `git diff --cached | grep -nE 'AIza[0-9A-Za-z_-]{10,}|BEGIN PRIVATE KEY'` で確かめる
- 失敗時は利用者に分かる日本語の文を返し、原因の手がかりは `detail` に（長い英数字は伏せる）
- .gs を変えたら `SCRIPT_VERSION` と `src/scriptVersion.js` を上げる。利用者には貼り直しと「新しいバージョン」での出し直しを伝える
- 画面の文は、現場の人が読んで分かる短い日本語にする

## 4. 仕上げの流れ（毎回）

1. `npm test` がすべて通る。画面を変えたら Playwright で開いて確かめる（スマホ幅も）
2. コミット → push → PR → マージ（利用者の指示があるときだけ PR を作る）
3. 本番の URL を `curl` して、新しく入れた文字列が出ていることを確かめる
4. 使い方が変わったら、利用者向けの案内・マニュアルを更新する
5. 日本語で報告する。利用者がやること（スクリプトの貼り直しなど）は最後にまとめて書く

## よくあるつまずき

- Google から HTML のエラー画面が返る → 公開設定が「全員」か、デプロイが新しいバージョンかを確かめる（`/api/health` で版を見る）
- 「合言葉が一致しません」→ .gs の TOKEN と環境変数 `APPS_SCRIPT_TOKEN` が同じか
- 環境変数を変えたら Cloudflare Pages で出し直さないと反映されない
- ログインが保たれない → 起動時の通信失敗で通行証を消さない。端末の保存はブラウザに消されることがあるので、
  HttpOnly の Cookie にも置いて戻せるようにし、開くたびに期限を延ばす（SBS配送ツールの `api/login.js` の `resume`）
- シートが日付の列を Date に変える → .gs で `dateText_` のように文字に戻してから返す
