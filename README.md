# 縁 野菜配送（ルート配送アプリ）

取引先「縁」の野菜をルート配送するためのアプリです。SBS配送ツール（km1121-design/-Tool-）の `starter/` から作っています。
作り方・決まりごとは `.claude/skills/field-app-starter/SKILL.md` に従います。

- 保存先：Googleスプレッドシート（Apps Script）／ホスティング：Cloudflare Pages
- ログイン：利用コード（シートの「利用者」タブ。SBSと同じ人＋追加）
- 出発地点：〒175-0082 東京都板橋区高島平７丁目３５−３ メゾン新高島平（`src/domain/route.js` の `DEPARTURE`）

## 1日の流れ（ドライバー）

1. 利用コードでログインし、配送日を確かめる（コースは曜日で自動。水曜＝水曜コース、日曜＝日曜コース、ほかはコース表）
2. 「配送リストを読み込む」でその日の PDF を選ぶ → 読み取った内容を確かめて保存
   - ✔ がある行だけを配る（コース表）。✔ が1つも無ければ全部を配る（水曜・日曜コース）
   - 順番はリストのとおり。1便・2便の区切りは配送先に表示する
3. 「出発」を押す → 配送先ごとに「道案内」（Googleマップ）→ 届けたら「完了」
   - 「出発地点からまとめて道案内」は 10 件ずつ。途中からは「今いる場所から残りを道案内」
4. 急な追加は「急な追加」から（何番の次に入れるかを指定できる）
5. 最後に「終了」を押す → 日当タブに 日付・名前・コース・件数・出発・終了 が入る（1便・2便は分けない）

同じ日のリストを読み込み直しても、完了にした分と、手で足した分は残ります。

## シートのタブ

| タブ | 列 |
| --- | --- |
| 利用者 | 名前 / 利用コード / 有効 / 区分（「管理者」なら日当を全員分見られる）/ メモ |
| 配送 | 配送ID / 日付 / コース / 順番 / 便 / 会社名 / 住所 / 備考 / 追加 / 完了時刻 / 完了者 |
| 日当 | 日当ID / 日付 / 名前 / コース / 予定件数 / 完了件数 / 出発 / 終了 / 更新日時 |

配送タブにはキーボックスの番号なども入ります。シートの共有は必要な人だけにしてください。
本物の配送リスト（PDF）はリポジトリに入れません（試験は作りものの見本で行います）。

## 設置（はじめの1回）

保存先のスプレッドシート「縁 野菜配送（データ）」は作成済み（タブ・見出し・日本時間・書式なしテキストの設定まで）。

1. そのスプレッドシートで「拡張機能 → Apps Script」を開き、`apps-script/endpoint.gs` の全文を貼る
2. `TOKEN` を長い合言葉に書き換えて保存 →「デプロイ → 新しいデプロイ → ウェブアプリ」（実行: 自分 / アクセス: 全員）
3. Cloudflare Pages →「Workers & Pages → 作成 → Pages → Git に接続」でこのリポジトリを選ぶ
   - プロジェクト名 `enishi-haisou`（URL が https://enishi-haisou.pages.dev になる）
   - フレームワーク: なし／ビルドコマンド: 空欄／出力ディレクトリ: `public`
4. 「設定 → 環境変数」に `APPS_SCRIPT_URL`（デプロイの URL）と `APPS_SCRIPT_TOKEN`（合言葉）を入れて出し直す
5. 「利用者」タブに 名前 / 利用コード / 有効（空欄で有効）/ 区分（事務は「管理者」）を書く
6. https://enishi-haisou.pages.dev/api/health で `"scriptVersion":1` と `"scriptReady":true` が出れば完了

合言葉・利用コードは GitHub やチャットに書かず、Apps Script と Cloudflare の入力欄にだけ入れてください。

## PDF の読み取りについて

ブラウザで pdf.js（jsdelivr から読み込み）を使って文字と位置を取り出し、サーバーの決まった計算
（`src/domain/route.js` の `parseListItems`）で行を組み立てます。AI は使いません。
見出しの「会社名・住所・備考」の位置を列の目印にするので、見出しの言葉は変えないでください。
写真をスキャンした PDF（文字が入っていないもの）は読めません。

# 現場アプリのひな形（field-app-starter）

SBS配送ツールで使っている骨組みだけを抜き出したものです。
**スプレッドシートを保存先**にして、**利用コードでログイン**する、スマホ向けの小さなウェブアプリをすぐ作れます。

| 入っているもの | 場所 |
| --- | --- |
| 利用コードのログイン（署名つき通行証・90日。呼び出しのたびにシートで有効か確かめ直す） | `src/auth/` `api/login.js` |
| シート（Apps Script）を呼ぶ部品（タイムアウト・HTMLエラー画面の1回呼び直し・合言葉の伏せ字） | `src/storage/appsScript.js` |
| シート側の受け口（利用者タブ・記録タブ・管理者・版の番号） | `apps-script/endpoint.gs` |
| 業務の例：記録の保存と一覧・合計（決まった計算） | `api/records.js` `src/domain/records.js` |
| 設置の状態（シートの版が古いと分かる） | `api/health.js` |
| Cloudflare Pages の入口 | `functions/api/[[route]].js` |
| 画面（ログイン・入力・一覧・管理者は全員分） | `public/index.html` |
| 本物の .gs を模擬シートで動かす通し試験 | `test/` |

## 新しいアプリにする

1. このフォルダを新しいリポジトリにコピーする（GitHub の「テンプレートリポジトリ」にしておくと、ボタン1つで複製できる）
2. `src/domain/records.js`・`api/records.js`・`apps-script/endpoint.gs` の記録タブを、そのアプリの業務に合わせて書き換える
3. `npm test` が通ることを確かめる

## 設置（はじめの1回）

1. 保存先にするスプレッドシートを作り、「拡張機能 → Apps Script」に `apps-script/endpoint.gs` を貼る
2. `TOKEN` を長い合言葉に書き換え、「デプロイ → 新しいデプロイ → ウェブアプリ」（実行: 自分 / アクセス: 全員）
3. Cloudflare Pages でこのリポジトリをつなぐ（ビルドコマンドなし・出力 `public`）
4. Pages の環境変数に `APPS_SCRIPT_URL`（デプロイの URL）と `APPS_SCRIPT_TOKEN`（合言葉）を入れて出し直す
5. シートに「利用者」タブができたら（初回のアクセスで自動作成。無ければ手で作る）、
   `名前 / 利用コード / 有効 / 区分 / メモ` の行を足す。区分を「管理者」にすると全員分が見られる

合言葉・利用コード・API キーは GitHub やチャットに書かず、環境変数の入力欄にだけ入れてください。

## 手元で動かす

```
cp .dev.vars.example .dev.vars   # 中身を自分の値に（.dev.vars は Git に入らない）
npm run dev                      # http://localhost:8788
npm test
```

## シート側を変えたとき

`endpoint.gs` の `SCRIPT_VERSION` と `src/scriptVersion.js` を同じ数だけ上げ、スクリプトを貼り直して
「デプロイを管理 → 編集 → 新しいバージョン」で出し直します。`/api/health` の `scriptVersion` が古いままなら貼り直し忘れです。
